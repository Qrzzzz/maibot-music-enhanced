# 兼容性与验收范围

## 1.2.1 数字选歌与撤回

数字选歌只处理同一聊天内发起人对有效候选的纯数字回复。有效期默认 90 秒，可以调整。自动撤回通过 Host 的 `api.call` 调用 SnowLuma 适配器公开撤回 API，仅处理 QQ 聊天中列表发送回执给出的数字消息 ID。没有回执、没有可用撤回接口或客户端拒绝时，候选仍按设定到期。

数字回复路由、跨平台合并及撤回调用由离线测试覆盖。真实 QQ 环境中的发送回执和撤回效果依赖适配器、客户端和撤回时限。

## 1.2.0 兼容范围

Host 声明 `1.3.15–1.3.99`，SDK 声明 `2.16.0–2.21.0`。实际隔离加载、重载和卸载验证使用 Host `1.3.19` / SDK `2.21.0`，CI 在 SDK 两个端点各运行回归。区间声明不等于逐版本运行验证。选歌身份使用 Host 命令/工具上下文中的 user_id，不从客户端查询，不开放给模型作为参数。

候选以 `(stream_id, user_id)` 隔离；群聊、私聊、多用户、过期、翻页、换源、取消及并发防重复由离线交互测试覆盖。卡片使用标准 music 段，QQ 平台详情取得的数字 ID 与 MID 分开；不可用时明确回退链接。新增功能无需客户端专用能力。

本版不包含图片歌单、签名自定义卡片、QQ 官方机器人按钮或新增音乐平台。真实 NapCat / SnowLuma 仍需分别完成群聊、私聊的候选、选歌和卡片显示/播放验收；本机运行目录未被本次开发替换。

## 1.1.1 的兼容声明

插件类型显式声明为 `tool`。Host 允许范围为 `1.3.15–1.3.99`，SDK 仍限定为 `2.16.0`。这表示采用同一 `1.3` 系列补丁兼容策略，不表示已经运行过尚未发布的所有补丁版本。

实际 Host 加载、配置重载及卸载验证使用 MaiBot `1.3.15` / SDK `2.16.0`。另用该 Host 自带的官方 manifest 校验器检查版本区间：`1.3.15`、`1.3.16`、`1.3.99` 应通过且不出现兼容模式 warning，`1.3.14`、`1.4.0`、`2.0.0` 应拒绝。这些是版本规则检查，不是对应版本的运行实测。

未来 Host 补丁若同时升级 SDK，仍需满足单独声明的 SDK 范围；本版没有放宽 SDK 或跨 `1.4` 系列的兼容声明。

## 推荐路线

`点歌插件 → MaiBot SDK → Host → 统一 QQ 适配器 → NapCat 或 SnowLuma`。

推荐使用 [MaiBot-SnowLuma-Adapter](https://github.com/Mai-with-u/MaiBot-SnowLuma-Adapter)。虽然名称包含 SnowLuma，它是支持两类客户端的统一连接器；客户端差异由连接器处理。本插件不管理客户端 HTTP 令牌，也不直接访问其发送或查询接口。

## 本版已覆盖的合约

| 组合 | 覆盖范围 |
| --- | --- |
| 插件 + 实际 SDK 能力代理 | 群聊、私聊流 ID 经 `cap.call / send.custom` 传递，语音使用 `voiceurl`，不查群号或用户号 |
| 官方 NapCat 旧适配器编码方法 | 语音转换为 `record`，本地路径转换为 `file://` 引用，数字 ID 转换为标准平台卡片 |
| 官方统一 QQ 适配器编码方法 | 相同的语音和卡片输入合约；该连接器可以连接 NapCat / SnowLuma |
| 卡片降级 | QQ MID 补查数字歌曲 ID；元数据不匹配或查询失败时回退公开链接；标准卡片失败同样回退链接 |
| 配置迁移 | 旧缓存读取目录保留，新字段优先，废弃 NapCat HTTP 配置与凭证不进入模型 |
| 下载边界 | 聚合及原生下载共用域名规则，重定向逐跳检查，异常后释放缓存引用并清理临时文件 |

旧 [MaiBot-Napcat-Adapter](https://github.com/Mai-with-u/MaiBot-Napcat-Adapter)当前 manifest 标明不再更新。因此测试保留其已有发送格式，但新的部署优先选择统一连接器。

## 真实部署仍需验收

本次 SDK、编码合约及隔离 Host 检查不发送 QQ 消息。下面项目必须在各自的实际客户端环境逐项确认，不能用 Mock 或编码测试代替：

1. NapCat、SnowLuma 分别连接统一 QQ 适配器，群聊和私聊均能点歌。
2. QQ 中实际收到且能播放语音，歌曲身份及完整时长正确。
3. 同机、容器或共享目录中，客户端确实能读取缓存文件。
4. Host 发送链路记录、聊天历史、真实消息回执与失败原因符合预期。
5. 卡片不可用时链接可用，且工具不将链接发送表述为语音播放成功。
6. 失败或投递未确认时检查客户端与适配器日志，避免手动重复操作造成重复消息。

在真实验收完成前，本版结论为“支持双端的 SDK/消息格式合约”，而不是“双端真实 QQ 全流程已通过”。如果 NapCat 出现实际兼容阻碍，应记录具体客户端、适配器版本和失败链路，再决定是否暂时收窄支持范围。
